1. Quick start

  1. Click the FASTA you want primers for in the Files panel.
  2. Open Tools › Primers and Probes › Design.
  3. Under Settings, pick the Mode (for an ordinary pair keep Standard PCR).
  4. Click Run. A report <your file>_primers.html opens next to your FASTA, and the best pair is drawn on the sequence.
Every window has Cancel, Save (keep the settings without running) and Run. A ? next to a field explains it. Clicking a file in the Files panel fills the path field you are editing.

2. Where to find it

Tools └─ Primers and Probes ├─ Design design PCR primers or FISH probes ├─ Map test primers against sequences └─ Database the lab's primer inventory Help └─ Primers and Probes Manual (this page)

The toolbar can also show a Primers and Probes button (Settings › Toolbar › Add buttons…). Click it for the same three items: Design, Map, Database. A right-click on it designs with the saved settings, or opens the Design window (choose which on its Options tab).

3. The Design window

Tabs: Primers | Regions | Specificity | Options. You can run from the first tab; the others are optional.

Inputs

  • Use selected sequences (default): the FASTA selected in the Files panel. Its name is shown under the button. Click another file to switch.
  • Define inputs: type or Browse a Template FASTA for this run, or click it in the Files panel while the field is active.

Every sequence in the template file is used (up to 20). For the TE alignment modes the file must be an alignment (same length rows, with gaps).

Settings

Mode is the kind of design. The list is grouped; the grey headings are only labels:

PCR primers General Standard PCR qPCR copy number Satellites Ladder PCR TEs Conserved in a family Subfamily-specific TE present or absent Methylation Bisulfite (BSP) Methylation-specific (MSP) FISH probes Satellites Satellite repeat oligos Chromosomes Chromosome painting (Chorus2)

Changing the Mode loads sensible starting values (size, Tm, product size) for that kind of design. Restore Defaults brings them back. The fields that only apply to one Mode appear when it is chosen.

Advanced Settings ▸ (bottom left) shows poly-X, GC clamp, 3′ stability, probe size and Tm, 5′ tails (M13, T7, restriction sites, or your own) and the Tm calculation (salt, Mg²⁺, dNTP, oligo concentration). When the window would be taller than your screen, the settings scroll and the buttons stay at the bottom.

Options tab

  • What a right-click on the toolbar button does.
  • Add the best pair to the sequence annotations (on by default): the primers and the product appear on the sequence view. A new run replaces the old primer annotations.
  • Add the designed primers to the Primer Database and which database to use.
  • Process window behaviour.

5. Regions and Specificity tabs

Regions

  • Target region: the product must span these coordinates (1-based).
  • Included region: primers only inside these coordinates.
  • Repeat Masking: keep primers out of soft-masked (lower case) bases, annotated repeats, tandem repeats, a RepeatMasker .out / GFF / BED file, and test against a Mispriming library (a FASTA of repeats).

Specificity

Check every pair against a genome counts binding sites and products of each pair in a genome FASTA (both strands, with the mismatches and 3′ rule you set). With Drop pairs with more than N products unspecific pairs are removed. A 3.5 Gb genome takes about 3 minutes.

6. Chromosome painting (Chorus2)

Choose Mode › FISH probes › Chromosome painting (Chorus2). The tabs change to Chorus2 | Selection | Options (the Mode box is on the Chorus2 tab too, to switch back).

Chorus2 (Zhang et al. 2021) finds oligos that occur once in the genome, along every chromosome. RepeatViewer runs it, or reads what it produced on a server, and then picks the pool you order.

Chorus2 tab

  • Run Chorus2 here: give the Genome; optionally Paint only one chromosome or region (a FASTA with the same names). A genome of a few Gb takes hours and much memory: a server is better.
  • Import results from the server: choose the Chorus2 BED. The genome is optional here (it only gives chromosome lengths for the plot).
  • Chorus2 settings (as in Chorus2): probe length (45 nt), max homology (75 %), min dTm (10 °C), k-mer step (5 bp), ploidy, threads, and the conda env.
  • NGS Filter (optional): genomic reads give each probe a k-mer score; probes in the lowest and highest score quantiles (default 10 % and 90 %) are dropped.
  • Copy Server Command: the exact command lines for the server, with your settings.

Install Chorus2 (once)

Chorus2 needs an older pandas than RepeatViewer, so it lives in its own conda env called chorus2 (on your Mac / Linux, or on the server):

conda create -n chorus2 -c conda-forge -c bioconda python=3.9 "pandas<2" numpy cython pyfasta "primer3-py<2" pybigwig pybedtools kmer-jellyfish bwa
conda run -n chorus2 pip install --no-deps git+https://github.com/zhangtaolab/Chorus2.git

The Chorus2 tab shows a ✓ when the env is found. On Windows run Chorus2 on a Linux server and import.

On the server

conda activate chorus2
Chorus2 -g genome.fa -i genome.fa -s chorus2_out -t 16 -l 45 --homology 75 -d 10 --step 5 --ploidy 2 --docker True

Copy chorus2_out/genome.fa.bed back (or probes_kmer_score.bed after the NGS filter) and import it. --docker True only stops Chorus2 from asking questions when an index already exists.

7. Results

Next to the input file:

gene.fa_primers.html            the report (opens in RepeatViewer)
gene.fa_primers_details/
   gene.fa_primers_primers.fa     every primer (FASTA, order-ready names)
   gene.fa_primers_pairs.tsv      table of pairs
   gene.fa_primers_gel.svg        virtual gel
   gene.fa_primers.json           all results (for re-use)

The report shows the pairs (Tm, GC, hairpin and dimer ΔG, product size, notes), the virtual gel, genome counts when checked, and a Methods text paragraph you can paste into a paper. A second run gets _2; if you choose the same name, you are asked before it is replaced.

8. Map: test primers on sequences

Like Geneious' Map Primers. Tabs: Map Primers | Options.

  • Inputs: Use selected sequences or Define inputs, as in Design. Test primers on: every sequence, or the consensus of an alignment.
  • Primers: either Test specific primers (type a sequence or pick a saved primer with the list button) or Search for saved primers that match (from the Primer Database or a primers FASTA; Forward / Reverse / Probe, Pairs only).
  • Products: optional included region, target region, product size range, optimal size.
  • Mismatches: maximum mismatches, and how many 3′ bases must match exactly.
  • Advanced Settings: Tm conditions, and counting sites and products in a genome.

Output: <file>_primer_map.html with binding sites, predicted products and a gel; sites and products are added to the sequence annotations.

9. Database: the lab's primer inventory

The Database is the record of every primer the lab has: its sequence and checks, what it amplifies and in which organism, where the tube is, whether it is in stock and whether it worked, who ordered it and when, and every change since.

Share it with the lab (Sciebo)

  1. One person: Change… › Use a Shared Folder (Sciebo)… and choose a folder inside the lab's shared Sciebo folder. RepeatViewer makes a folder RepeatViewer Primer Database there and offers to copy the primers you already have.
  2. Everyone else: Change… › Open Another Database… and choose that folder in their own Sciebo folder.
  3. The first time you change something, RepeatViewer asks your name; it appears in the history. Change it with Change… › Your Name in the History….

Each person and computer writes only its own change log (log/<name>@<computer>.jsonl), so Sciebo never has to choose between two versions of one file and no change is lost. Changes from others appear after Sciebo has synced (the window checks every few seconds). If two people change the same field of one primer, the later change wins; changes to different fields are both kept. Without a shared folder the database lives on your computer only.

Move the lab sheet in (once)

In Google Sheets: File › Download › Microsoft Excel (.xlsx) or Comma-separated values (.csv). Then Import… and choose the file. RepeatViewer finds the header row and reads the columns it recognises: Primer name, Primer sequence, Organism, Amplified sequence (Target), Tm (supplier), H2O added (Dissolved), Ordered by, Ordered on, Located in Box, Freezer, Room, and also Status, Tested, Annealing, Concentration, Pair, Note when present. Before importing it shows how many primers are new, which are already in (same sequence, even under another name: that name is kept as Other names), and which rows are skipped and why. Importing again later only adds what is new.

The window

  • Filter searches every field (name, sequence, target, box, who …); the boxes next to it show one organism, the primers of one person, or one status.
  • People: everyone in the lab is one entry, so Ordered by is chosen from a list (Choose…), not typed. A primer can have several people. Add someone new from Choose… › Add Person… or People…. In People… you can set a role and email, rename (every primer shows the new name), Merge two entries for one person (e.g. Anna and Anna K.), and Remove: someone who ordered primers stays as a former member (grey), so the record of who ordered what is kept. The sheet's “Anna & Nusrat” became two people, Anna and Nusrat. The first time you change something, pick yourself from the list.
  • Pair is found from the names (_for/_rev, _fwd/_rev1, _FW/_RV, _F/_R); write it in Pairs with when the names do not show it (for example ITS1-F with ITS4).
  • Select a primer to edit it below the table, then Save Changes. Select several to set a field on all of them at once (for example a new box or Used up).
  • The panel on the right shows Tm, GC, hairpin, self-dimer, the Tm from the synthesis report, and the history. Select two primers to see the dimer between them.
  • Find Duplicates: the same sequence under two names, reverse complements, and one primer inside another.
  • Export…: the whole table (every field, .tsv opens in Excel), a FASTA, or an order sheet.
  • Designed primers are added (with status Designed) when Add the designed primers to the Primer Database is on in Design › Options.

Check a new sequence against the stock

Someone new brings their plant: before designing and ordering, see what the lab already has. Click the sequence (a gene, contigs or a genome) in the Files panel, then Check a Sequence… in the Database window (or Map with Search for saved primers). Every saved primer is tested on both strands, with up to 2 mismatches but the last 3 bases at the 3′ end exact. The report starts with From your Primer Database:

  • Ready pairs: two saved primers that give a product, with the product size, mismatches in each primer, and where the tubes are. Saved pairs, exact matches and pairs that worked before come first. A primer with mismatches can still work, but test it; mismatches near its 3′ end matter most.
  • Single primers that bind: no saved partner gives a product. One new partner primer is enough to use them.
  • Nothing usable: design new primers.

10. Methylation (BSP and MSP) in plants

Bisulfite turns unmethylated C into T; methylated C stays C. The Methylation field says which C may be methylated:

SettingC that may stay CC counted as converted
Plant (CG, CHG, CHH) (default)CG and CHG (often fully methylated). CHH is only partly methylated.CHH
Animal (CG only)CGCHG and CHH
  • BSP primers contain no C that may be methylated, so both forms amplify. Min converted C asks each primer to cover some converted C, so unconverted DNA is not amplified.
  • MSP places the 3′ end of the M and U primers on a site. MSP 3′ end on: CG (classic) or CHG (plants only, tests the CMT3 / KYP pathway).
  • Converted strand: after conversion the two strands are no longer complementary; pick the one to amplify.
In plant mode fewer C count as converted, so in GC-rich or CHG-rich regions BSP may find nothing with Min converted C = 3. Lower it to 1 or 2, allow longer primers, or try the other strand.

11. When nothing is found

The report then explains why (for example how many primers failed on Tm, GC or overlap with masked regions). Common fixes:

  • Widen the Tm range or the Product size.
  • Turn off some Repeat Masking options (Regions tab) if the template is mostly repeat.
  • Conserved / Subfamily-specific: lower Min coverage, allow more Mismatches tolerated or a higher Max degeneracy.
  • TE present or absent: annotate the TE on the locus, or fill TE position; increase Max flank distance.
  • MSP: needs CG (or CHG) sites near both ends of a product; widen the size or Tm range.
  • Genome check dropped everything: allow more products, or design in a less repetitive part.
  • Painting: too few probes for the pool size: lower the gap, widen the regions or the NGS score window, or rerun Chorus2 with a smaller k-mer step or higher max homology.

12. How it works

Primer picking, Tm and the thermodynamic hairpin and dimer checks use Primer3 (primer3-py). Binding-site search (Map, coverage on copies, genome check) is RepeatViewer's own: an exact 3′ seed search with mismatches allowed on the rest, on both strands. Degenerate primers, ladder, FISH oligos, TE present or absent, BSP and MSP are built on top of these. Chromosome painting uses Chorus2 (MIT licence) in its own conda env. Everything runs on your computer (or your server); nothing is sent online.

Primer3: Untergasser et al. (2012) Nucleic Acids Research 40:e115.
Chorus2: Zhang T, Liu G, Zhao H, Braz GT, Jiang J (2021) Plant Biotechnology Journal 19:1967-1978.
